# HushNest 跨平台需求与交付记录

记录日期：2026-11-01（Asia/Shanghai）。本文件汇总本次对话中确认的需求及最终实现，供后续开发、验收和维护使用。桌面交付版本为 **0.4.0**；Web / Android 当前应用版本为 **0.1.0**，使用相同的跨平台长助眠音包。

## 范围与集成约束

- 原有原生 iOS 工程继续维护；新增多端实现放在 `cross-platform/`，先在 `codex/web-android-windows` 开发，再集成到 `main`。
- 本轮目标为 Web / PWA、Android、Windows，并按后续需求加入原生 macOS 客户端。
- macOS / Windows 使用 MyGo 的原生 Go UI，窗口不创建 WebView，不打包 React 页面、Electron 或 Chromium。Android 采用 Capacitor 页面及原生服务；原生 UI 的要求针对桌面客户端。
- 集成前已同步主分支 `5000d1e` 的 iOS 1.6.0 长音频更新。本次集成保留该版本的 iOS 代码、M4A 音频、工程配置、测试、官网与原有工作流；跨平台使用独立 WAV 音包。
- 主分支合并采用可追溯的 Pull Request / merge commit，保留开发历史及开发分支。跨平台 CI 覆盖 `main`、开发分支和相关 PR。

## 已确认需求与验收标准

| 编号 | 需求 | 最终行为与验收标准 |
| --- | --- | --- |
| R01 | 增加 Web、Android、Windows，保留 iOS | 多端代码独立存放并可构建；与集成前最新 `main` 比较，原生 iOS 及官网文件无本轮额外改动。 |
| R02 | Web 去掉耳机判断 | Web 开始、恢复和试听不要求耳机检测或二次确认；输出随系统设备变化，设备变化不据此中断计时。 |
| R03 | macOS / Windows 使用 MyGo 原生界面 | 使用 MyGo 0.7.3 `ui` 包和 Go 后台；实际窗口 `Page() == nil`；桌面资源无 HTML / JS / CSS。 |
| R04 | 改善客户端样式 | 原生侧边导航、圆环计时、声音卡片、足迹统计；支持主题、深浅外观、六种语言、大字体和紧凑窗口。 |
| R05 | 客户端识别耳机，包括有线耳机 | Windows 通过 WASAPI 端点类型判断；macOS 读取 CoreAudio 输出及系统提供的插孔状态。设备信息不足时进入手动确认流程。 |
| R06 | 检测不到耳机时二次确认后放行 | 桌面端有可用输出时弹出设备名称，用户明确确认已连接耳机后放行；取消不播放。确认绑定当前设备，只在本进程有效；设备改变或重启后失效。没有输出设备时不能放行。 |
| R07 | 部分唤醒铃声无法听清试听 | 桌面内置 14 种闹铃从第 12 秒试听 4 秒，使用所选闹铃音量；正式响铃仍从开头并渐强。助眠音、自定义音轨从开头试听。 |
| R08 | 试听再次点击可以停止 | 桌面播放时按钮切换为停止，再次点击立即停止；切换声音、试听到时或输出改变后恢复按钮状态。 |
| R09 | 助眠音更长、减少短片段重复 | 使用下表的 5～10 分钟音轨；自然音为长连续实录并作首尾交叉衔接；噪音整段重新生成，不能通过复制旧短片段充数。 |
| R10 | Windows 安装报文件写入错误 | 默认使用当前用户可写目录 `%LOCALAPPDATA%\Programs\HushNest`；支持覆盖升级、空格及中文路径；许可证、音频组件和所有音频必须完整安装。受保护目录仍遵循系统写入权限。 |
| R11 | 合并 GitHub 主分支并留存本次需求文档 | 本文件、构建说明、第三方录音来源与校验清单随代码进入主分支；保留 PR、提交历史与 CI 验证记录。 |

## 跨平台长助眠音包

| 场景 | 原跨平台音轨 | 0.4.0 音轨 |
| --- | --- | --- |
| 细雨 | 55 秒 | 10 分钟 |
| 潮汐 | 85 秒 | 10 分钟 |
| 溪流 | 65 秒 | 6 分钟 |
| 林间 | 70 秒 | 8 分钟 |
| 炉火 | 22 秒 | 5 分钟 |
| 夏夜 | 44 秒 | 8 分钟 |
| 棕噪音 | 30 秒 | 10 分钟 |
| 粉红噪音 | 30 秒 | 10 分钟 |

六种自然音选自 CC0 长录音，统一处理音量并保留动态余量，以 12 秒等功率交叉渐变衔接首尾。两种噪音使用覆盖完整 10 分钟的周期频谱生成，不复用短噪音块。输出为 24 kHz / 16-bit PCM WAV；保留自然录音的立体声，夏夜和噪音为单声道。原有 14 种闹铃继续从 iOS 资源中复用。

新音包位于 [assets/sleep](../../cross-platform/assets/sleep/)。[FieldRecordings.json](../../cross-platform/assets/sleep/FieldRecordings.json) 保存作者、公开来源、许可、截取位置、时长、源文件和输出 SHA256，以及峰值、RMS、循环边界和短周期相关性检查结果。[第三方说明](../../cross-platform/THIRD_PARTY_NOTICES.md) 随包提供。

Web 在首次使用时缓存完整音频并支持字节范围请求；音频缓存名称由资源内容计算，更新后不会复用旧短音轨。Android 和桌面客户端随包提供音频，可离线使用。长期存储、分发和安装体积相应增加，音频不在每次构建时重新下载。

## 平台行为与限制

| 平台 | 界面与计时 | 输出及耳机行为 | 交付形式 |
| --- | --- | --- | --- |
| Web / PWA | React 页面；依赖页面和设备保持可运行 | 不检查耳机，跟随系统输出 | 静态 `dist/`，缓存界面及已使用音频 |
| Android 9+ | Capacitor 页面、原生前台服务及 wake lock | 原生路由校验；蓝牙需确认设备类型 | 调试签名 APK；正式上架需独立签名配置 |
| Windows x64 | MyGo Go UI、Go 会话后台 | .NET 8 / NAudio WASAPI 固定端点；未识别时二次确认 | 当前用户 NSIS 安装器及完整便携目录 |
| macOS 12+ | MyGo Go UI、Go 会话后台 | Swift / CoreAudio / AudioQueue 固定设备 UID；未识别时二次确认 | Apple Silicon / Intel 通用 DMG，当前为 ad hoc 签名 |

有线耳机是否能自动识别取决于系统及声卡驱动是否暴露正确端点或插孔状态。若声卡始终报告同一“扬声器”端点，应用可能无法察觉 3.5 mm 物理插拔；此时由用户确认实际声音来自耳机。桌面输出改变时停止声音并进入中断状态，不能自动回退到扬声器。

Web / Android 的播放器不属于本轮“桌面 4 秒试听及播放/停止按钮”改动范围。Web 不保证锁屏或后台提醒可靠。实体设备的热插拔、蓝牙切换、来电、驱动差异及电池管理仍需硬件验证。当前工作没有发布商店版本或替换现有官网。

同步的 iOS 主分支基线 `5000d1e` 已通过其独立 [iOS 功能与交互测试](https://github.com/ZanwingMak/HushNest/actions/runs/41220005258)。跨平台资源测试已适配该基线使用 M4A 自然音的布局；跨平台播放继续使用自身 WAV，iOS 文件摘要按上游清单核验。

2026-11-01 本机 Windows 已从 0.3.2 更新到 0.4.0：确认没有活动休息后安装，核对休息状态文件摘要未变化，并逐一验证安装后的 8 段长音轨 SHA256、真实原生解码及界面。自动化仅做无声解码，不自动播放音频。

## 维护入口与重建

- [多端运行、构建及安装说明](../../cross-platform/README.md)
- [跨平台 CI](../../.github/workflows/multiplatform.yml)
- [统一音频资源打包](../../cross-platform/scripts/stage-audio.mjs)：复制原闹铃并使用跨平台独立长音包；资源缺失时构建失败。
- [长音包生成脚本](../../cross-platform/scripts/prepare-sleep-audio.py)：只写入跨平台目录；`--verify` 检查现有输出，`--download` 校验公开 CC0 来源后重建。
- [公开音源下载工作流](../../.github/workflows/sleep-audio-sources.yml)：手动运行，保留源文件和许可证据，产物保存 7 天。
- [音包生成工作流](../../.github/workflows/build-sleep-audio.yml)：在开发分支手动运行，输入下载工作流的 run ID，验证后将生成资源提交到开发分支；不直接写入 `main`。

所有构建直接使用仓库中的最终音频。维护者需要更换录音时，应更新来源、许可和截取参数，再重建音包、复查摘要与分析结果，并通过 CI 后合并；不要用跨平台脚本覆盖原生 iOS 资源。
